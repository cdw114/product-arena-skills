# Parameter table

The table is generated by `emit_outputs.py` as `parameter_table.md` and
`parameter_table.csv`. This file records the shape and the rules, so a hand-written table
can match it.

## Shape

| eid | parameter | value | unit | applies to | source | status |
|---|---|---|---|---|---|---|
| E0010 | `train.batch_size` | `64` | samples | dataloader | `materials/config.yaml#/train/batch_size` | ok |
| E0042 | `weight_decay` | `0.1` | 1 | optimiser | `materials/train.log:11` | conflict |
| E0012 | `train.weight_decay` | `0.01` | 1 | optimiser | `materials/config.yaml#/train/weight_decay` | conflict |

## Rules

1. **One row per (parameter, value, source).** A value repeated in three log lines is one
   row; a value that differs between two sources is two rows, both kept.
2. **`unit` is never blank in the reader's mind.** Use `1` for dimensionless rather than
   an empty cell, and `name` for a value that is a symbol rather than a quantity
   (`adamw`, `bf16`).
3. **`applies to` says what the value acts on**, not where it was found: `optimiser`,
   `dataloader`, `model`, `training loop`, `learning-rate schedule`. The source column
   already says where it was found.
4. **`source` is a locator, not a filename.** `materials/config.yaml` alone is not enough:
   the reviewer needs `#/train/learning_rate` to land on the line.
5. **A row with `status: conflict` is not resolved in the table.** Both rows stay, both
   appear in the prose, and `open_questions.md` asks which is authoritative.
6. **The prose and the table share the ledger.** If a number is in one and not the other
   for the same parameter, one of them is wrong — the audit catches this by requiring each
   table row to corroborate a value it cites.

## Unit vocabulary

Use these spellings so the table stays sortable:

`1` (dimensionless), `samples`, `tokens`, `steps`, `epochs`, `runs`, `GB`, `GPUs`,
`ratio`, `name`, `version`, `%`.

## What does not belong in the table

- Loss values, accuracies and other *results*. Those go in the results section; a
  parameter table that mixes settings with outcomes cannot be used to re-run anything.
- Derived quantities you computed (effective batch, total steps) unless you also record
  the inputs they were derived from. If you keep them, mark the row's source as the
  derivation, not a file.
